## 唯一来源

- 参数存档：`design/approved-ui-20260905.json`

## 页面壳归为三类（分类契约，不是迁移完成数量）

| 页面 | 结构 | 固定规则 |
| --- | --- | --- |
| 一级页 | 标题 + 可选右侧操作 + 底部导航 | 左右20px；标题栏44px；标题到首个内容4px |
| 二级页/全屏编辑页 | 返回 + 标题 + 可选右侧操作 | 与一级页共用宽度、标题栏和正文节奏；操作在标题栏第三列 |
| 上下文弹层 | 标题 + 简短内容 + 操作 | 短任务编辑、确认、授权和危险操作；正文组件仍复用下表 |

一级页和二级页的同级内容组间距都是16px。页面左右默认20px，视口不超过360px时按现有公共断点统一为16px，不允许页面自行选值。顶部使用系统安全区，一级页底部为导航与安全区留位。禁止页面单独修改标题位置、左右边距或组间距；禁止绝对定位返回键和标题栏操作。

### 页面到代码的归属

静态代码有13处`node('main', …)`和39处`dialogShell()`调用，不等于52种设计模板；同一入口可能渲染多个业务状态，也有通过通用函数构建的设置页。

| 业务范围 | 页面壳归属 | 当前构建入口（src/app.ts） |
| --- | --- | --- |
| 今日、任务、记录 | 一级页 | `todayPage`、`tasksPage`、`recordPage` |
| 轨迹下的日历、本周、成长 | 一级页的内容视图 | `calendarPage`、`weeklyReviewPage`、`growthPage`；通过`trailTabs`切换，不另设字体等级 |
| 设置 | 一级页 | `systemPage` |
| 某日回顾 | 二级页 | `dayPage` |
| 任务分析、习惯分析总览/详情 | 二级页 | `taskAnalysisPage`、`habitAnalysisOverviewPage`、`habitAnalysisPage` |
| 状态详情、自评、长表单、目标/习惯/记录详情、设置详情 | 二级页/全屏编辑 | `dialogShell`加`full-screen-editor`及`addDialogBack`；需逐入口核实组合完整性 |
| 短任务编辑、日期快照、授权、删除确认 | 上下文弹层 | `dialogShell`与相应入口；不应借背景页的几何数据验收 |
| 首次选角色 | 上下文弹层的引导状态 | `showOnboarding`，不是新的页面字体系统 |
| 普通加载失败、数据库恢复 | 页面错误状态 | `render`的catch、`renderDatabaseFailure`；后一种不依赖正常数据库或导航可用 |

页面标题构建集中于`pageHeader`/`secondaryPageHeader`；弹层由`dialogShell`构建，返回由`addDialogBack`组合。当前不是一个统一的页面组件函数，仍需要检查每个组合调用点。

## 普通文字归为四级（含明确的语义变体）

| 角色 | 规格 | 使用范围 |
| --- | --- | --- |
| 页面标题 | 16px / 800 / 1.2 | 当前页面名称 |
| 组件标题 | 14.5px / 800 / 1.35 | 分组、区块、表单大区标题；例如“正文”“相关记录” |
| 正文 | 12.5px / 400 / 1.5 | 列表名称、日记、说明、输入内容；任务标题不加粗 |
| 辅助信息 | 11.5px / 400 / 1.35 | 日期、数量、状态和必要补充信息 |

按钮和表单小标签沿用12.5px，仅允许500字重表示可操作性，不产生新的字号层级。统计数字和图标是专用显示元素，可使用 `--ui-font-metric` 与 `--ui-font-icon`，不得拿来显示普通标题。现有日记使用1.55行高的特殊规则、任务打卡次数采用正文大小的规则需明确保留或合并，不能隐瞒为已经完全一致。

| 容易混淆的内容 | 应归属 |
| --- | --- |
| “正文”“相关记录”“服务信息” | 组件标题，不是小字段标签 |
| 任务/习惯/设置入口名称 | 正文，即使HTML当前使用h3或strong也不应自动加粗 |
| 名称、日期等小字段标签；保存/删除按钮 | 正文大小，控件500字重变体 |
| 历史日期、保存状态、列表右侧状态 | 辅助信息；需同时指定字号、字重和行高 |
| 必要风险提示、错误原因 | 信息主体用正文；不能仅因颜色较淡就自动降为辅助字号 |
| 周期大数字、五维分数、图标 | 专用数据/图形，不计为第五级普通标题；大小仍须有公共令牌与明确用途 |

实现规则：`.ui-page-title` 是页面标题；`.ui-list-heading` 和页面/弹层中的普通 `h2/h3` 是组件标题；`[data-ui-row]` 内的 `h2/h3` 自动降为正文；`.caption/.muted/.empty-copy` 是辅助信息。不得用页面名选择器重写这些角色。

## 基础组件归为七组（不是全应用只有七个组件）

| 组件组 | 公共结构 | 合法差异 |
| --- | --- | --- |
| 标题栏 | `.ui-titlebar`、`.ui-page-title`、`.ui-back-button` | 一级/二级结构；可选右侧操作 |
| 内容分组 | `.ui-list-section`、`.ui-list-heading`、`.ui-stack` | 标题文字与内容数量 |
| 列表 | `.ui-list-group`、`.ui-list-row` | 只读、导航、操作、控件四种行为；几何不变 |
| 内容容器 | `.surface`、`.ui-panel`、`.ui-surface-plain` | 有边界、紧凑、有意无框 |
| 表单 | `.field-label`、`.ui-form-stack`、`.input` | 单行、多行、日期、选择器 |
| 操作 | `.button`、`.ui-actions` | 主、次、轻、危险四种语义颜色 |
| 选择 | `.ui-segmented`、`.ui-filter-tabs` | 固定分段或可横向滚动筛选 |

日历、热力图、人物和徽章允许专用内部布局，但必须继续使用同一页面、标题、正文、按钮和颜色体系，不能形成另一套页面壳。

### 组件的唯一负责位置与例外

| 组件 | 结构来源 | 尺寸来源 / 检查要点 |
| --- | --- | --- |
| 标题栏 | `pageHeader`、`secondaryPageHeader`、`dialogShell`/`addDialogBack` | `design-system.css`；禁止页面定位补丁 |
| 列表与内容分组 | `src/ui-list.ts`的`listRow/listGroup/listSection/infoRow/taskRow` | 同一行基础几何；四种行为不是四套皮肤 |
| 表单 | `labelledControl`、`.field-label`、`.ui-form-stack`及大区label | 小字段间距4px、字段组11px、大区标题间距13px分别归属 |
| 按钮、分段和筛选 | 多个业务入口组合公共类 | 共享CSS不代表DOM已全封装；主动状态、禁用、焦点需分别检查 |
| 内容框与提示 | `.surface/.ui-panel/.ui-surface-plain/.privacy-boundary` | 有框/无框由内容用途决定，不根据页面编号决定 |
| 反馈与浮层 | `showToast`、确认弹层、更多菜单、折叠详情 | 属于跨页面交互组合，尚无完整实时样板；不能遗漏于验收范围 |
| 专用内容 | 日期网格/热力图、人物/徽章、日记编辑区、统计图 | 保留业务布局，统一外部页面壳和普通文字；内部固定尺寸需登记用途 |
| 底部导航 | `bottomNavigation` | 属于跨页面导航组件，独立检查等宽、点击区、安全区和选中态 |

“七组”只用于管理基础样式。反馈、导航、特殊内容由基础组件组合，不强行塞进普通列表；没有完成迁移的结构必须保留待办。

### 间隔职责（不可相互借用）

页面标题到内容、组件标题到内容、同级分组之间、字段标签到控件、字段之间、行内元素、操作按钮之间，分别由对应容器负责。`.ui-actions/.ui-actions-pair/.dialog-actions`现在统一使用独立的`--ui-action-gap`；修改组件标题间隔不得再影响按钮间隔。

### 列表契约

- 所有普通列表共用45px最低行高、左右20px、上下0、8px圆角和1px分隔线。
- 外框与圆角属于 `.ui-list-group`；组内行不再各自画卡片。
- 只读行不显示箭头；导航行才显示箭头；操作行承载完成、打卡、计数和更多；控件行承载开关或选项。
- 列表内部的空状态使用统一列表行；整页错误、加载和无记录首次使用提示属于页面状态，不强制包成列表行。
- 长内容按内容增高，不截断正文；普通单行标题可以省略，完整文字保留在可访问名称或详情中。

## 自动审计

代码清单：`node scripts/audit-ui-code.mjs --output design/screenshots/20260906-template-audit/code-audit.json`；脚本自检：`node scripts/audit-ui-code.mjs --self-test`。

解析4个CSS文件，记录直接尺寸和同选择器/同条件下重复不同值，列出`app.ts`页面、弹层及动态样式调用位置。输出包含文件和行号。只生成清单，不自动删除，也不将成功退出解释为符合规范。

修复后静态清单：旧CSS有2076条目标属性直接尺寸声明、580次重复不同值；公共CSS只剩2条随字体缩放的1em图标尺寸；手写原型CSS有42条。统计排除自定义变量定义，包含可能已被覆盖的旧规则，不等于独立缺陷数。修复前为2101/588及公共CSS7条，人物5条已集中到令牌。

合理例外：人物专用尺寸、1em图标、1px边框、断点、安全区/键盘视口以及数据驱动图表值。固定像素不自动违法；问题是普通组件绕过公共令牌，或同一语义由多处定义。人物尺寸归属`--ui-portrait-*`，不用于普通列表或文字。

`scripts/capture-ui.mjs` 用隔离数据运行真实页面并输出55张截图，同时读取实际 DOM：

- 页面左右20px、标题栏44px、标题到正文4px。
- 页面标题必须为16px/800；组件标题必须为14.5px/800；列表内标题必须为12.5px/400。
- 列表行最低45px、左右20px、上下0；独立行圆角8px。
- 日历、热力图等方格保持正方形；内容不得横向溢出。

标题几何、已有列表规则和已识别文字角色的字号/字重/行高均作为断言；`text-audit.json/html`保留失败明细。新增静态测试禁止旧CSS重新定义已迁移辅助字体、禁止公共组件尺寸直接写px；浏览器回归覆盖页面/弹层、不同文字标签和200%字体，并验证标题间距与操作间距互不联动。

本轮将标题、列表、图表和文字测量统一限定于活动页面/弹层；没有公共标题栏时输出`shellCoverage.measured=false`，不能回退测量背景页面。55张截图是采样场景，不是全应用所有状态。当前6个上下文弹层没有可测公共标题栏，已单独标记；不代表它们必须改成全屏页面。

测试失败时修改共享来源，不得在出问题的页面末尾补一个覆盖。人工优先确认公共模板的视觉密度；开发仍负责真实页面、内容变化和未覆盖状态的复核，不能把剩余逐页测量工作转交给用户。

## 禁止事项

- 同一语义出现第二套字号、字重、行高、圆角、按钮高度或列表内距。
- 业务页面新增公共尺寸的硬编码 `px`；新尺寸必须先判断能否复用现有令牌。
- 根据页面编号或页面名称创建“紧凑版2”一类样式。
- 用全局缩放掩盖组件尺寸问题。
- 用截图目测或调参页通过代替真实页面 DOM 审计。
- 将必要的隐私、错误、危险提示删掉；普通介绍性文字则应尽量缩短。
