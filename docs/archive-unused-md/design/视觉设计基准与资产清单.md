## 0. 视觉方向结论

本轮已经形成一套可以指导后续高保真原型和正式美术生产的视觉基准：

- 平台感：跨平台移动端，使用稳定的顶部安全区和五入口底部导航。
- 情感中心：一间固定像素房间和唯一生活分身。
- 信息语言：Neo-brutalism 的粗描边、方角、硬阴影与直接层级。
- 场景语言：原创 16×16 基础网格、温暖木质房间、克制的 16-bit 像素感。
- 角色语言：偏成人比例、安静亲切、日常服装，不使用幼儿化或奇幻化造型。
- 产品气质：温暖、可靠、略带游戏感，但首先是一套能长期使用的个人工具。

## 1. 设计圣经

### 1.1 平台与画布

- Cross-platform premium neutral。
- 核心设计宽度以约 390 CSS 像素的竖屏手机为起点。
- 正式实现必须适配 320、390、430 CSS 像素宽度，不照搬视觉稿的图片尺寸。
- 顶部安全区、底部手势区和键盘弹出状态必须独立验证。

### 1.2 色板

| 用途 | 基准色 |
| --- | --- |
| 纸张与主背景 | `#FFF7E6` |
| 主文字与描边 | `#211E1A` |
| 主要行动 | `#FF6B4A` |
| 习惯与生长 | `#68A85B` |
| 信息与时间线 | `#59B8D1` |
| 待确认与注意 | `#E0A72E` |
| 严重风险 | `#C83E3E` |

规则：

- 主页面只允许一个珊瑚色主要行动。
- 绿色不表示“好用户”，只表示生长或已确认完成。
- 红色不表示任务失败，只用于删除、危机或不可逆风险。
- 所有颜色含义同时配文字、图标或结构差异。
- 不使用紫蓝启动公司渐变、玻璃态、霓虹和大面积柔和渐变。

### 1.3 字体

- 长中文使用清晰的系统无衬线字体。
- 像素字体只用于 `MAIN 01`、`TODAY`、等级和极短标签。
- 正文不小于 16 CSS 像素；辅助信息不能小到需要放大图片阅读。
- 正式实现不把视觉稿中的字形当作图片素材。

### 1.4 描边、阴影与形状

- 主要面板：2 至 3 CSS 像素深色描边。
- 主要操作：4 至 6 CSS 像素硬边偏移阴影。
- 圆角：0 至 4 CSS 像素；设备外框不属于产品组件规范。
- 同一页面只设置一个最强阴影层级。
- 列表优先使用分隔线，不把每一行都做成独立卡片。

### 1.5 图标

- 使用 16 或 24 逻辑像素的原创像素图标。
- 同一组图标保持相同描边、视觉重心和填充方式。
- 图标必须配文字；不依赖用户猜测含义。
- 正式实现前先制作导航与六件家具所需的最小图标集，不生产大而全的图标库。

## 3. 像素场景与角色资产

### 3.1 房间基准

[room-baseline.png](../../../design-assets/pre-development/room-baseline.png) 为 1361×1156 像素场景参考。

它固定以下规则：

- 单一房间，不扩展地图。
- 六个功能地标：日记桌、任务板、日历、书架/工作台、窗边/床、生活分身。
- 三个习惯花盆集中放置，房间内不增加容易混淆的装饰植物。
- 中央留出角色站立和短路径移动空间。
- 房间成长物件以后只能添加在不破坏路径和热点辨识的位置。

这张图是构图与气氛参考，不直接作为游戏背景切图。正式场景需要重新按确定的逻辑像素网格绘制。

### 3.2 角色原画与动作基准

用户原创头像：

- [鹿角头饰男生卡通头像](../../../design-assets/pre-development/avatar-male-cartoon.png)
- [牛纹帽双辫女生卡通头像](../../../design-assets/pre-development/avatar-female-cartoon.png)

对应动作参考：

- [男生动作基准](../../../design-assets/pre-development/character-motion-male.png)
- [女生动作基准](../../../design-assets/pre-development/character-motion-female.png)

固定规则：

- 原画直接用于头像选择、对话和复盘；不融合、不重画、不改变性别。
- 两套像素动作分别对应原画，只解决房间中的小尺寸动作需求。
- 正面、侧面和背面保持各自头饰、发型、服装与锚点一致。
- 两套都包含四方向行走、待机、伸展、喝水、写日记、看任务板、倾听、点头和欢迎挥手。
- 同一时间只启用一套外观，切换不会创建第二个角色或清空成长数据。

## 4. 页面差异化节奏

| 页面 | 节奏 | 最强视觉对象 |
| --- | --- | --- |
| 今日 | 情感先行 | 房间与生活分身 |
| 记录 | 安静、聚焦 | 大输入区 |
| 日历 | 叙事、追溯 | 某日摘要与证据时间线 |
| 任务板 | 行动明确 | 今日唯一主线 |
| 成长 | 稳定、可解释 | 当前成长分支与经验来源 |
| 复盘 | 章节感 | 下周期唯一重点 |
| 系统 | 严肃、可控 | 当前人生章节与权限 |

七个页面不能简单复制同一种卡片模板。页面构图可以变化，但底部导航、色板、描边、图标和文字层级保持一致。

## 5. 生成稿审查与修正记录

已经完成以下针对性修正：

1. P01 首页移除额外装饰植物，只保留三个习惯花盆，避免与习惯数量产生歧义。
2. P04 任务反馈框移除麦克风图标，明确语音来自系统输入法，而不是 App 自建录音。
3. 五入口导航把“过去”统一改为“日历”，P03 页面命名改为“某日回顾”。
4. 习惯任务统一显示为用户主动选择的 `BONUS` 任务；任务板区分 BONUS 与支线。
5. 用户原创鹿角头饰男生与牛纹帽双辫女生成为两套正式头像，并分别建立动作基准。

已检查：

- 七页均保持五入口导航逻辑；复盘页作为聚焦章节可以不显示底部导航。
- 首页、某日回顾页和房间基准使用当前选中的同一生活分身与房间语言。
- 成长页没有人生总等级或排行榜。
- 任务板没有负分、失败红色、断签火焰或枯萎植物。
- 系统页删除操作保持严肃，没有使用角色动画弱化风险。

生成图仍有以下天然限制，正式实现不得照抄：

- 局部中文排版和图标需要使用真实 UI 组件重建。
- 像素场景中的物件尺寸需要按最终网格重新规范。
- 设备外框、系统时间和信号只是展示环境，不属于产品资产。
- 图片中的文字、任务和数值是演示数据，不是默认用户数据。

## 6. 正式美术生产顺序

1. 分别确认男生、女生标准正面帧和 32×48 逻辑像素是否可读。
2. 为两套头像分别生产四方向行走和基础待机，先在空房间中验证相同锚点与速度。
3. 重新绘制一间 16×16 基础网格房间和六个家具热点。
4. 生产六个家具终点动作。
5. 生产三个花盆的永久成长阶段与近期动量效果。
6. 生产任务盖章、XP 像素块、等级牌和周复盘翻页反馈。
7. 只有用户提供或批准新原画时才增加外观。

在两套基础角色和路径验证前，不批量生成家具和装饰物，也不自行增加换装。

---

## 7. 视觉交付验收标准

- 首页只出现一个中心角色。
- 房间只有三个习惯花盆，遗漏不会产生枯萎版本。
- 角色与家具在手机宽度下仍然能辨认。
- 每页只有一个最强操作。
- 中文正文不使用像素字体。
- 五入口导航保持稳定。
- 所有 AI 推断均有文字标签，不只依靠虚线或颜色。
- 系统和数据删除页面不使用游戏化弱化风险。
- 减少动态后，全部页面层级仍然成立。
- 视觉资产均保持原创，不复制具体游戏角色、场景或图标。

---

## 8. 本轮不等于正式美术定稿

本轮交付解决的是视觉方向和页面关系，不解决生产素材精度。正式开发前不需要继续生成更多页面变体；下一次图像生产只应服务于经过实现验证的角色 Sprite、房间图块或明确缺失状态。
